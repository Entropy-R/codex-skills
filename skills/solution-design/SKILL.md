# 02 实现方案设计

## 工作目标

基于“需求理解与澄清”阶段的完整输出和用户补充回答，生成成熟、清晰、可执行的工程实现方案。

## 输入

```text
第一阶段输出：
【粘贴需求理解与澄清阶段的完整输出】

用户补充回答：
【粘贴用户对澄清问题的回答；没有就写“暂无，按默认假设处理”】

现有技术背景：
【已有系统、语言、框架、数据库、部署环境；没有就写“暂无”】

方案偏好：
【默认：优先简单可靠地落地】
```

如果缺少第一阶段输出，要先提醒用户补充；只有在上下文中已经有等价信息时，才继续设计。

## 处理规则

1. 使用第一阶段中已经确认的信息，不要忽略澄清结果。
2. 若仍有关键缺口，先标出缺口，再给出带假设的方案。
3. 方案偏工程落地，不写泛泛产品愿景。
4. 任务拆分要能直接交给开发执行。
5. 对复杂逻辑、隐含业务规则、边界处理做明确说明。
